# 练习连接 HTTPS/WSS 对照（2026-11-16）

四档均完成，15,200 条已受理命令全部 COMMITTED。每场最终累计时长与确认序号一致；两档 WSS 各完成 20 次接管，通知 P95 均低于两秒。

## 场景与资源

本机 arm64 Colima，4 vCPU、6 GiB。API 576 MiB／256 MiB 堆，worker 384 MiB／192 MiB 堆，PostgreSQL 256 MiB，RabbitMQ 384 MiB，Nginx 网关 256 MiB。网关使用部署相同的不可变镜像、连接槽、文件句柄与 TLS 缓冲设置。每档升压 45 秒、保持 180 秒、退场 5 秒；HTTP 与 WSS 均经过真实 TLS 网关。Python 预检校验证书并确认认证升级成功；k6 使用隔离证书并跳过该测试证书的链校验。

每用户两次稀疏元数据保存，心跳三十秒一次；异步回执等待与心跳并行。普通保存保留幂等键并允许两分钟重试收敛，接管沿用服务端六十秒期限。账号、设备与场次为合成数据，档间重置版本、累计时长、确认序号和写入凭证并断言清零。

## 适用范围

本轮验证长连接、控制通知和稀疏同步的短时共存。题目条目为空，保存核对累计时长与序号；答案、标记、修订、当前位置及交卷完整性另由真实 HTTP/WebSocket 和两套设备存储联测覆盖。未据此认定完整题库浏览、集中交卷、生产公网与长时业务容量。
既有完整业务 2000 VU 场景的确认延迟 SLA 曾未通过，见[完整业务容量记录](../../../../docs/backend-capacity-results.md)；本轮准入改进后尚未重跑该完整场景。
诊断中确认旧 API 448 MiB 上限发生 OOM，已增加容器余量；同步接口的立即拒绝改为有界短等待，保留原并发预算。普通保存的退避和最终收敛仍分别报告。
