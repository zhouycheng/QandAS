# Preview and commit a ZIP

1. Review an unpacked working copy using the preparation skill, including existing packages. Check explanations, images and formulas before staging. Preserve the original file and portable IDs. For unassigned top-level questions, assign a local chapter key for their chosen destination in the working manifest and add its chapter record if needed. Map every source chapter record explicitly, including local keys added for unassigned questions, to a verified database chapter UUID. Validate the final manifest with its assets and package it at the ZIP root.
2. After destination confirmation, call `qanda_upload_zip(bankId, sizeBytes)`. PUT consecutive 4 MiB chunks at the returned URL using zero-based `part`; the final chunk may be shorter.
3. Call `qanda_preview_import` with `bankId` and `input: { uploadId, chapterMap }`. Inspect image errors, conflicts, new chapters and per-question changes. Resolve any unexpected chapter creation or destination mismatch before committing.
4. An import request authorizes additions at the confirmed destination. For updates show the actual field differences and obtain user confirmation. Call `qanda_commit_import` with the same bank, upload and mapping, preview digest and `expectedContentVersion` from preview's `contentVersion`. Set `confirmUpdates` only for confirmed updates. Reuse the idempotency key on an identical retry. Re-preview after changes to the archive, mapping or bank version and confirm any revised updates.
