## 管理端实际页面观察

使用本机显式 Mock 模式，在浏览器实际检查：

- 侧边栏在运营概览后显示活跃度监控；四张人数卡、7 日趋势和分页排行榜显示正常。
- 切换活跃天数、答题量和学习时长排序，表格顺序随选项变化；点击用户打开资料与学习摘要，学院、专业、年级正确显示。
- 题库工作台按课程进入目标题库，展示题目分页和章节计数；新建题目可选六类内容，阅读题组可以加入填空小题并独立设置可接受答案与匹配规则。
- 检查发现的下拉标签重复触发、Mock 用户详情缺少院系名称问题已修复并重查。

观察截图保存在本轮交付附件 `qanda-activity-verification.jpg`，页面数据为 Mock。完整真实数据联调、移动端触摸体验和长期性能需要对应环境另行验收。

## 复验入口与运行记录

从仓库根目录运行后端独立检查：

```sh
node apps/api/scripts/backend.mjs test
node apps/api/scripts/backend.mjs postgresTest '-Dit.test=PlatformPostgresTest#*,!PlatformPostgresTest#miniapp*'
```

第二条运行真实隔离 PostgreSQL 验收，明确排除连接小程序运行时的联调用例。本轮验证没有迁移、清空或重建已有开发数据库。测试使用的 PostgreSQL 和 SMTP 捕获服务由临时容器提供。

管理端、小程序分别在各自目录执行 `npm test` 和 `npm run build`。小程序真实编译命令和传参规则见 `apps/miniapp/AGENTS.md`。最后调整布局示例文案后另行执行 `node tests/fill-reading.check.js`，结果通过。

后端原始报告位于忽略目录 `apps/api/target/surefire-reports/`、`apps/api/target/failsafe-reports/`，本轮运行导出和去敏 HTTP 交换位于 `apps/api/.backend-runtime/verification/`。这些目录是本机过程证据，重新运行会覆盖。合同和 Postman 正式文件已同步到仓库。

## 真实联调前的条件

当前结构包含年级学年、前台心跳、课程开放关系、阅读材料及填空作答字段。旧开发库不会自动升级；结构不匹配时应用就绪检查会拒绝启动。下一阶段应准备按当前 v1.0 schema 初始化的开发环境，现有数据处置需另行明确。

本轮没有执行管理端 HTTP 模式与小程序真机的联合操作，也未对微信官方身份、真实邮件投递或并发容量作出验收结论。在线人数的延迟来自 120 秒过期窗口和监控页刷新周期；长期 CPU、数据库负载与真机离线图片恢复留待下一阶段实测。
