# 同步重构验证交接

## 当前交付

同步入口统一为 `sync-commands`，完整 SAVE／FINISH 任务先保存 PostgreSQL，RabbitMQ 只调度任务 ID。worker 按练习顺序处理，答案、结果和回执在同一事务提交；扫描器恢复未发布、重试和调度租约过期任务。暂时故障持续退避重试，已接收任务不受登录令牌自然过期影响，明确撤权仍生效，同账号重新登录后可重新授权原任务。未处理任务按练习及账号设置数量和字节预算，积压满时保留本机数据并退避。Redis 保留公共内容与按修订标识的选题候选缓存。

小程序持久保存本地变化和交卷意图，已发送命令固定内容与幂等键；恢复网络和重启后先对账再补传。练习记录以摘要分页展示，进行中继续作答，已结束以背题式布局展示原始选择及正确答案，并保留已作答简答题的自评入口。等待上传／批改时，即时反馈允许只读回看；交卷后反馈提示“批改中，不可进入”。

## 下一轮执行顺序

1. 从最新 `main` 开始，核对合并提交及 CI 结果，先复核最后的练习记录状态、分页和只读回看；确认列表渲染数据没有题目或完整答案，错误选项显示原始选择。
2. 运行 `npm --prefix apps/miniapp test`、`npm --prefix apps/miniapp run build` 和 `node apps/api/scripts/backend.mjs verify`。后端验收使用隔离容器；官方小程序编译与实际交互分别记录。
3. 部署前保存配置、容器状态及指定题小搭测试环境的数据库基线。本次直接调整初始化结构，现有测试数据库需要重建后再启动新版本；旧接口调用方须与本次代码同时更新。只处理明确指定的项目数据库及 RabbitMQ vhost，保留宿主机、其他项目、部署凭据和停止的旧 MySQL 资源。
4. 通过既有 `Deploy backend` Actions 发布 `main`。核对服务器实际镜像摘要、版本、健康状态与客户端接口；前端部署仍留在原服务器。本轮尚未验证新版本镜像是否可以完全通过 Actions 自主拉取。
5. 新建独立压测数据库和 RabbitMQ vhost，准备 20 个题库、10000 道合成题目及按并发档位扩充的独立账号。使用同一基线比较来源 IP 限流开启／关闭；普通账号业务限流保持已删除，认证及权限保持启用。
6. 先完成断网交卷后重启、丢失响应、RabbitMQ 暂停、worker 重启、数据库短暂不可用及 Redis 不可用的端到端恢复验证，再进入 1800 人与更高档位。停止新增负载后，对账全部本地交卷意图、已接收任务及正式成绩，核对待处理、重复成绩和答案差异均为零；稳定档持续 30 分钟。
7. 导出接收／处理吞吐、积压、P95／P99、等待与恢复时间及发压端指标。最终恢复原配置、监控与备份状态，清理本轮明确创建的测试资源；测试链路先饱和时仅报告已测下限。
