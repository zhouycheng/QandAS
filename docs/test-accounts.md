# 测试账号管理

管理端侧边栏的“测试账号管理”用于创建小程序学生测试账号。列表支持按登录账号或账号编号搜索、按状态筛选，并提供学生资料、查看凭据和提前停用操作。

## 创建和使用

新建时填写 1–365 的整数有效天数，默认 7 天。弹窗按完整的 24 小时推算北京时间的预计到期时间，最终以服务端创建时间为起点，成功后展示实际到期时间。

“计入运营统计”默认关闭，创建后固定。开启时，该账号计入用户总量、新增与留存、活跃和在线人数、排行、答题量及学习时长；停用后保留历史贡献。关闭时，账号个人的学习记录与统计仍完整保留。系统请求和队列指标记录实际负载。

系统按 `QANDATEST001@qanda.mail`、`QANDATEST002@qanda.mail` 的格式生成登录名，使用数据库序列递增，至少补足三位。并发创建不会重复，停用或创建回滚产生的编号不复用。登录名只用于系统内测试，匹配时忽略大小写；对应名称不接受普通注册、邮箱绑定或管理员分配给普通账号，也不发送邮件。

系统生成 16 位随机字母数字作为测试登录码，在账号有效期内固定。小程序复用现有邮箱登录表单，输入测试登录名后自动显示“测试登录码”，隐藏验证码发送、登录方式切换和密码找回入口。测试账号按普通学生权限使用学习功能，账号安全页面提示由管理员管理凭据。

有效期内，管理员可在原有“查看凭据”弹窗重复查看并复制账号和测试登录码。接口沿用 `password` 字段承载测试登录码；界面显示其实际用途。凭据弹窗关闭、账号切换或到期时清除内存中的登录码。复制到剪贴板的内容由操作系统管理。

## 停用和到期

提前停用需要确认，随后撤销全部会话并清除登录码哈希及加密材料，保留账号及学习记录。已停用账号不能重新启用。

登录、会话认证和事务内校验均检查测试有效期，异步答题消费同样执行该检查。会话到期时间不超过测试账号到期时间。worker 每分钟处理到期账号，每次最多 100 个，处理可重复执行；worker 暂停时，过期账号仍无法访问服务，恢复后继续完成停用处理。

## 接口和凭据保护

接口仅向超级管理员开放：

| 接口 | 请求与行为 |
| --- | --- |
| `GET /api/v1/admin/test-accounts` | `keyword`、`status`、`page`、`pageSize`；状态为 `ACTIVE`、`DISABLED`、`EXPIRED` |
| `POST /api/v1/admin/test-accounts` | `validDays`、`includeInStatistics`；返回账号元数据，HTTP 201 |
| `GET /api/v1/admin/test-accounts/{id}/credentials` | 返回有效账号的邮箱、密码和到期时间，登记查看审计 |
| `PUT /api/v1/admin/test-accounts/{id}/status` | `expectedVersion`；提前停用 |

写入携带 `Idempotency-Key`。创建响应及幂等回执只保存元数据；密码通过单独接口按需读取，响应使用 `Cache-Control: no-store`。账号资料的 `isTestAccount` 标记供客户端展示测试账号限制。

登录校验使用 `test_account.login_code_hash`，用户账号表不保存测试登录码哈希。可重复查看的登录码另以 AES-256-GCM 加密，密文绑定账号 ID，每次加密使用独立随机 nonce。登录验证继续执行失败限流，并以真实测试账号记录判定身份；邮箱格式只决定表单展示。查看日志只记录管理员、账号 ID 和请求 ID。监控角色仅能读取生命周期和统计字段。

## 配置与数据库

私有环境配置中增加：

| 配置项 | 要求 |
| --- | --- |
| `BACKEND_TEST_ACCOUNT_ENCRYPTION_KEYS` | 逗号分隔的 `version:base64` 密钥环；版本 1–32767，每把密钥解码后为 32 字节 |
| `BACKEND_TEST_ACCOUNT_ENCRYPTION_ACTIVE_VERSION` | 当前加密版本，默认 1，必须存在于密钥环 |

全新本地配置由 `backend.mjs init` 自动生成独立密钥。已有本地及生产配置需补充这两个字段，密钥保存在仓库外或被忽略的私有配置中。缺少可用密钥时，创建及查看凭据返回 503；到期校验和停用处理仍可运行。轮换时保留仍在使用的旧密钥版本，丢失旧密钥会导致相应密码无法再次查看。

`test_account` 和 `test_account_number` 序列包含在统一 V1 初始化结构中，应用与 API 版本保持 `1.0.0`。空库执行 V1 初始化，既有库校验结构。结构不一致时，按[开发与运行](development.md)核实专用开发／测试用途及恢复条件，再处理数据库和关联状态。

验收入口见[验收规范](verification.md)，后端专项为 `TestAccountPostgresTest` 和 `TestAccountCryptoTest`。
