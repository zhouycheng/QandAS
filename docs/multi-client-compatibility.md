# QandA 三端兼容规则

更新日期：2026-11-01。后端与合同基线为 v1.0（`1.0.0`），统一使用 `/api/v1`。本阶段提供管理端、小程序和后端的兼容实现及独立检查，真实三端联调另行进行。

## 各端差异与调整结果

| 业务 | 原有差异 | 当前统一处理 |
| --- | --- | --- |
| 院系与年级 | 管理端维护入学年份，小程序仅有学院，后端资料范围不统一 | 学院、专业、五档当前年级；首次完善资料，自由修改；按学年递增 |
| 内容范围 | 界面预览、目录和练习的筛选不同 | 后端统一资料匹配、全校范围及课程单独开放；游客浏览已发布内容 |
| 内容停用 | 管理端存在直接删除入口 | 课程／题目停用、题库下架／归档、仅空章节删除；保留历史与已发放快照 |
| 题型 | 管理端有填空、阅读，答题链只覆盖四类基础题 | 五种基础题型和阅读题组，贯穿预览、快照、离线作答、同步、结果及布局 |
| 内容发布／导入 | 客户端与后端标准和数量限制不同 | 统一发布检查；每批 3000 道实际作答题、8 MiB UTF-8 请求体，事务与幂等 |
| 管理数据 | 浏览器 Mock、全量读取与按页面聚合并存 | Mock/HTTP Gateway 同方法、分页、版本与错误；院级和概览聚合读取 |
| 活跃度 | 部分业务活动记录，缺少前台在线概念 | 独立前台心跳、去重人数、自然日趋势及三种排行榜 |
| 反馈 | 后端有反馈能力，小程序入口缺失 | 答题／详情纠错、无题库缺课需求、我的反馈记录，与管理端回复对应 |

## 资料与可见范围

注册或登录后，`GET /me` 返回资料完整状态；资料不完整时进入个人资料页，保存学院、专业和当前年级后返回原入口。保存使用 `expectedVersion`，用户可随时再次修改。

后端保存设置年级和对应学年，北京时间每年 9 月 1 日递增，大四之后为已毕业。未手动修改年级时更新昵称等字段不会重新起算；手动设置年级后以当前学年为起点。

登录范围为资料匹配、全校开放、课程单独开放的并集，同时要求课程启用、题库已发布和题目启用。课程开放名单覆盖以后新发布的题库。游客浏览全部符合发布条件的内容，并保留本机累计两次试答。账户、资料或学年变化使目录、搜索和选题预览缓存失效，旧响应不能覆盖新范围。

学院和专业停用后不供新资料选择，原资料保留；课程停用、题库下架／归档、题目停用后退出新练习范围。已发放的练习按固定修订完成，成绩和历史继续可读。收藏与错题保留，并返回 `available` 表示当前是否可重新练习。

## 内容与练习

- 判断答案传布尔值；填空逐空支持多个答案和统一的大小写／首尾空白匹配，全部空位正确才判整题正确。
- 简答提交后显示参考答案、可选评分要点并允许自评；统一反馈模式交卷后展示。评分要点最多 30 条。
- 阅读材料、基础小题使用稳定 ID 与不可变修订。题数、进度、答题卡和统计按小题计算，材料不计数。
- 普通、背题、模拟考试按完整题组抽取；错题／收藏可只选小题并携带材料。预览返回实际题数、题目 ID 与内容版本，创建复用同一选题结果；每次最多 1000 题，不拆开容纳不下的题组。
- 题干、材料、解析为安全文本、换行和独立图片附件。正式结果由后端重算；本机保留答案显示规则、草稿队列和离线判题。
- 完整题目及材料附件下载、校验并落盘后才开始试答；存储失败不扣额度。正式创建响应丢失使用原意图和幂等键重试。
- 练习写入所有权、业务版本与本机确认序号继续分开管理，接管和重复交卷遵守原同步协议。

## 活跃度监控

管理端侧栏“运营概览”后为“活跃度监控”，路由 `/activity`，超级管理员可访问。人数卡始终表示当前时点；趋势和榜单周期分别选择。

| 指标 | 口径 |
| --- | --- |
| 在线 | 有效学生会话在最近 120 秒收到前台心跳，按用户 ID 跨设备去重 |
| DAU | 北京时间今天有前台访问或有效学习活动的学生数 |
| WAU / MAU | 含今天的最近 7 / 30 个自然日去重学生数 |
| 活跃趋势 | 近 7 / 30 日每日活跃，空日期补零 |
| 活跃天数榜 | 活跃天数降序，再按答题量 |
| 答题量榜 | 已提交正式练习的作答小题次数降序，再按活跃天数 |
| 学习时长榜 | 已提交正式练习时长降序，再按答题量 |

各榜并列后按用户 ID 排序，默认每页 20 条；支持今日、7 日、30 日、累计。同一练习重复提交只计一次，不同正式练习重复作答按次数累计。用户详情展示资料及正式学习摘要。

学院、专业和年级按用户当前资料归属过滤，可叠加客户端条件。小程序登录成功和回到前台立即心跳，前台每 60 秒一次；隐藏停止，失败不积压补传，认证失效暂停。后台草稿同步不更新前台在线时间。

监控页可见时人数每 30 秒刷新、趋势及当前榜单每 60 秒刷新，切页或浏览器隐藏即停止。失败保留最近成功数据和更新时间。PostgreSQL 复用按用户、客户端、日期的活跃表，并为前台会话时间和日期查询建立索引。在线人数是近实时估计，异常断连需要等待 120 秒窗口及下次页面刷新。

## 合同、运行与阶段边界

接口集合共 129 项，页面调用及未使用项见[逐接口台账](miniapp-api-integration.md)。管理端以 `VITE_API_BASE_URL` 选择 HTTP 模式，缺省为显式本机 Mock；账号、目录、题库、反馈和统计适配器共用合同。

当前数据库结构定义在 `apps/api/src/main/resources/db/schema.sql`，保持 v1.0。新字段、索引和课程开放关系随空库初始化建立，本阶段的 PostgreSQL 检查使用隔离容器。现有开发库未执行迁移、清空或重建；旧结构启动会被就绪检查拒绝，真实联调前需要准备符合当前结构的开发环境。

邮箱提醒、头像及偏好仍为本机能力，界面和台账明确标注。用户上传题库入口继续关闭。独立测试、编译和页面观察范围见[验收记录](multi-client-compatibility-verification.md)。
