# 前端架构规范

## 微信小程序

Page 处理微信 API、事件、导航、焦点和动画；ViewModel 返回数据与页面命令；Model 和 utils 处理可独立验证的规则；Repository 管理 API、缓存、快照和草稿。共享资源使用 MobX 和官方绑定库。

正式内容读取统一经过 API。请求去重、分页、身份隔离、资料范围失效和迟到响应保护放在仓储中。前台请求最多四个并发，后台草稿最多占用一个槽位。

练习状态、内容投影和同步状态分别维护。计时只投影计时字段；作答结果转为字段及数组项补丁，再调用 `setData`。稳定的整卷数据不随每次点击重复传输。原生输入聚焦期间，计时和同步更新不回写输入内容。

`practice-session.js` 协调作答状态、计时和恢复；`practice-presentation.js` 计算题目、答题卡及参考答案展示，`practice-results.js` 负责结果与筛选投影。题库 ViewModel 协调请求、分页和答题配置，`bank-detail-presentation.js` 组装科目、章节和分组展示。题库搜索走服务端分页，错题与收藏的筛选和统计读取服务端集合接口。

界面文案面向学生与内容管理员：说明当前状态、操作结果和可执行的下一步。配置项、协议转换和重试实现写入开发规范；导入格式要求、监控指标含义等影响用户操作的信息在对应界面说明。

自定义导航统一计算状态栏与胶囊空间，路由使用原生微信 API。组件样式保持隔离；浮层使用统一 portal 和安全区规则。共享答题模板同时用于练习、结果和布局编辑。

## 管理端

页面依赖 `AdminContentGateway`，HTTP Gateway 负责认证、协议转换、幂等和错误处理。TanStack Query 管理远程资源，Zustand 管理界面偏好。业务规则放在现有纯函数模块；表单保持原生受控行为。

路由按业务页面延迟加载。样式按公共基础、组件、布局、题库工作台和运营页面分文件，保持原有层叠顺序。列表使用服务端分页，选择器按需加载并补全已选资源名称。

## 模块维护

顶部导航栏或面包屑已显示页面名称时，正文直接呈现内容和操作；分组、题库或章节名称按实际上下文保留。

按职责拆分文件，手写业务文件超过 1000 行时必须重新核对边界。生成的合同、锁文件及数据库字典按其生成源维护。跨模块调整同步更新调用方、类型、测试和文档，保留输入校验、权限、错误处理及可访问性。
