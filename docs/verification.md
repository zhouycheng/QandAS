# 验收规范

## 自动检查

共享包执行 `npm --prefix packages/content-format test`。管理端在 `apps/admin` 执行 `pnpm test` 和 `pnpm build`，包含 TypeScript 未使用检查。

小程序在 `apps/miniapp` 执行 `npm run build`、`npm test`。编译检查调用微信官方 WXML / WXSS 编译器，分别核对进程失败、模板行列诊断及样式 `ERR`。本机未安装编译器时的跳过状态必须单独记录。

后端在仓库根目录执行：

```sh
node apps/api/scripts/backend.mjs test
node apps/api/scripts/backend.mjs verify
```

完整验收使用隔离 PostgreSQL、RabbitMQ、Prometheus 和邮件捕获容器。合同、HTTP Schema 和 Postman 的生成检查见[接口验收入口](../apps/api/acceptance/README.md)。测试报告与去敏运行证据放在 Git 忽略目录，记录实际执行范围。

## 业务回归

核对注册登录、账号资料和安全操作、目录权限、内容维护、导入发布、所有题型、联合题库、即时及统一反馈、计时、错题收藏、自评、统计、公告群码、反馈和管理监控。同步核对重复提交、账号切换、迟到响应和存储失败。

单设备恢复覆盖离开页面、切后台、重启、断网作答和响应丢失；其他设备不能编辑进行中的练习。游客额度、偏好和布局分别验证。

错题收录开关覆盖关闭后不收录新错题、开启后收录、已有错题继续更新、错题筛选与练习范围一致，以及成绩和正确率保持完整统计。交卷重试保持第一次提交的偏好和幂等键。

暂停消费者后，进度应可靠积压；恢复后按原命令确认。重复消息仅落库一次，技术失败可重试并进入死信，管理员可恢复。未完成进度阻止正式交卷，恢复后只产生一份成绩。队列与监控均属于核心验收范围。

## 性能记录

同一环境、相同数据量比较 20、100、1000 题：微信实际包体、请求数、`setData` 字节数、SQL 次数和响应时间。管理端比较入口及业务异步块。容量检查独立记录 HTTP 接收、队列积压、消费及落库速率和延迟。

Node 数据量测量不能代替真机流畅度，浏览器构建结果不能代替页面检查。真机触摸、键盘、原生返回、长期断网恢复及容量压测分别记录实测结果。
