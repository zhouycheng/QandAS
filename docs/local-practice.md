# 本地练习与内容一致性

小程序完成判题、整卷批改和简答题自评，云端保存客户端结果并提供学习统计及跨设备读取。交卷先可靠保存最终作答、逐题结果和上传意图，再显示“已完成”；网络和服务端延迟不阻塞查看本机结果。

## 题目与答案

每场练习固定题目修订和阅读材料修订。题库内容从 A 更新到 B 后，新练习采用 B，进行中的 A 保留完整配套内容。历史成绩保持当时结果，题目更新通过独立的新版入口展示。

`answer-vault` 将标准答案、填空匹配资料、参考答案、解析和评分要点保存到微信加密存储。分块在写入后读回校验，全部成功后发布普通快照引用。每块明文按 UTF-8 字节数限制为 256 KiB，给字符串编码和加密膨胀留出空间。普通快照和上传正文不包含标准答案，成绩通过题目条目 ID 复用同一份题干与材料，减少整卷重复存储。进入当前题及交卷时异步读取对应资料；隐藏页面释放模型内判题资料，再次显示时恢复。账号切换拒绝迟到响应，注销清理该账号的加密内容和缓存。

内容检查调用 `POST /content/revision-status`，每批最多一百个题目引用。同一范围五分钟内合并请求，恢复联网和页面显示时触发；新建练习直接使用创建接口的内容版本前置条件，冲突时重新获取范围后重试一次。新内容与附件完成保存后切换最新指针，固定练习引用保持原修订。

## 结果保存

`SAVE` 上传合并的作答、状态及客户端逐题结果，`FINISH` 上传完整作答、整卷汇总及本机完成时间。云端沿用本机完成时间归属学习日期，跨日恢复网络也保持统计日期一致。服务端检查题目归属、修订、作答形状及汇总结构，批量保存答案和选项。结果、回执和序号在一个事务提交。回执提供结果 ID，完整历史结果通过结果接口读取。

首页与统计将本机结果按练习 ID 合并。读取汇总时同时询问哪些本机练习已计入，只有未计入的结果才叠加，防止响应丢失时重复计数。简答题自评先保留本地，之后通过幂等请求写入；汇总在同一数据库视图中返回待确认自评的实际保存值，客户端只叠加差额。

## 验收入口

运行小程序 `npm test`、`npm run build`，后端运行 `node apps/api/scripts/backend.mjs verify`。`client-practice.check.js` 覆盖加密分块、修订匹配、20／100／1000 题本地计算和共享退避；`ClientResultsPostgresTest` 使用真实数据库验证客户端判定原样保存、修订拒绝及重复提交。`live-backend.cjs` 经实际 HTTP 完成小程序交卷与自评。

微信原生加密在真机上的兼容性、实际触摸与长期断网恢复分别验收。Node 测量只用于逻辑和数据量对比。远端容量验证使用隔离数据，普通六十秒同步、集中交卷、集中恢复网络及内容更新分别记录；稳定档持续三十分钟后再提升档位。

- 后端完整隔离验收通过：50 项单元检查、95 项集成检查。存储引用调整后另跑 16 项同步集成检查，通过实际 HTTP 完成小程序交卷、自评与恢复。

- 小程序逻辑检查与官方 npm 构建通过；41 份 WXSS、39 份 WXML 官方编译通过。版本检查覆盖仅修改答案、解析、选项、阅读材料、下架、下载期间再次更新，以及下载失败后重新读取新版。
- 管理端 80 项测试与构建通过；压测工具 46 项、部署脚本 48 项、后端运行脚本 4 项检查通过。压测工具检查用于验证发压与对账逻辑。
- 打包镜像在临时 PostgreSQL、RabbitMQ、Redis 中完成空库初始化、重复初始化和 readiness 检查；临时容器及网络已清理。
- 20／100／1000 题的 Node 加密模拟与本地批改检查通过；服务端整卷保存对应 17 次 MyBatis 执行，JDBC 准入及回执语句另计。这些观察不能代表真机耗时或远端并发容量。

本次发布使用空数据库及配套客户端缓存。发布前清理指定测试库、关联队列和旧小程序缓存，API、worker、monitor、小程序与管理端配套发布。回滚只能使用能够识别当前结果与加密资料的构建。

真机原生加密、触摸操作和 1800／2000 人远端容量测试尚未执行。离线及已经开始的练习继续保留当时修订，可能包含后来被纠正的答案；设备清理或丢失可能损失尚未上传的记录。
