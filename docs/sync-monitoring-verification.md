## 可靠同步与权限

已验证的路径包括：

- 暂停消费者后返回 `202`，数据库练习版本保持不变；重复原命令得到同一状态，变更正文或同场新增命令被拒绝。
- 等待落库期间，交卷、取消和交出写入权被屏障阻止；完成后正常交卷。
- 模拟发布确认丢失后使用原键重发；模拟事务已提交而 ACK 未执行，再让真实队列副本消费，业务版本只递增一次、回执只有一份。
- 技术失败达到 8 次进入死信，经平台管理员处理恢复；重复处理使用幂等键；已完成命令的重复死信清理后不重复写入。
- 队列中的会话失效、旧写入凭证分别终止处理，保留原练习版本；其他学生无法读取命令状态，学生无法恢复死信。
- 小程序 `202` 后恢复进程仍保留原正文、原键、序号及待确认草稿；新答案不被旧回执清理；存储失败提示并先重试本机保存。
- 原有断网练习、答案展示时机、简答自评、游客试答和跨端接管检查继续通过。

确认丢失及提交后 ACK 丢失使用确定性的故障点模拟；本次未执行进程崩溃时的磁盘损坏或断电试验。

## 故障边界与 SSE

| 场景 | 实际观察 |
| --- | --- |
| 暂停 RabbitMQ | 提交返回 `503`，命令保留 `ACCEPTING`；个人资料、公开目录、公告仍返回成功。恢复后原键提交只落库一次 |
| 锁住公告表 | 公告查询超时返回 `503 TEMPORARILY_UNAVAILABLE`；同时读取个人资料、目录及保存练习进度均成功，解除锁定后公告恢复 |
| 停止消费者 | 消息保留并产生排队；恢复后处理并确认 |
| 终止独立 monitor JAR | 核心进度保存和公告继续成功；监控连接池使用受限角色和查询超时 |
| 暂停 Prometheus | 快照变为 `STALE`，保留上次采样时间和指标 |
| 监控角色权限 | 可读公开视图，禁止修改练习、成绩、内容修订、活跃聚合、同步命令和事件；失败审计仍可追加 |
| SSE 权限撤销 | 真实 HTTP 流收到 `auth-expired` 后关闭 |
| Nginx 转发 | 上游持续连接 30 秒的受控 SSE 服务，其首事件在 5 秒内经真实 Nginx 到达；认证头转发成功 |
| 管理端流式读取 | 分片、多行事件、CRLF、重连退避、取消订阅、旧回调和非法指标检查通过 |

Nginx 用例验证流式传输和代理配置；真实后端 SSE 用例分别验证快照及权限。本次没有将管理端浏览器连接到整套真实 Compose 环境。

## 计数与负载观察

以下为开发机上的功能性负载观察，不作为容量上限。

### 暂停积压再恢复

12 场独立练习，各提交 1 条进度，发送间隔 500ms；消费端 4 个消费者、每个预取 1 条。

| 项目 | 结果 |
| --- | --- |
| 暂停消费时 | 排队 12、处理中 0、消费者 0 |
| broker 发布计数增量 | 12 |
| broker ACK 计数增量 | 12 |
| 唯一成功命令 | 12，每场业务版本仅增加一次 |
| 恢复后的队列 | 排队 0 |
| 观察用时 | 14,738ms，包含主动暂停和等待指标抓取 |
| 测试 JVM CPU 时间 | 990ms，包含请求、轮询与采集 |
| 窗口平均／p95 同步延迟 | 6,249.15ms／9,370.86ms，包含主动积压等待 |
| 当时生产／消费速率 | 均约 0.2545 条/秒 |
| 当时唯一落库速率 | 约 0.2333 条/秒 |

速率采用完整的最近 60 秒窗口，其中包括相邻验收用例的命令；RabbitMQ 速率由 Prometheus 根据采样点估计。该快照不能直接按本用例的 12 条消息除以 60 来比较。精确对照使用上述 broker 累积计数增量及唯一数据库命令数。

### 串行增量保存

4 题练习、并发 1、30 次进度保存：总用时 4,134ms，测试 JVM CPU 时间 957ms，响应合计 9,446 字节、平均 314 字节；单次完整练习读取响应 3,827 字节。未采集独立 PostgreSQL 进程 CPU，也未进行大规模持续压测。
