题库搜索使用服务端分页。目录投影只读取当前科目所需的章节及分组数据。构造每科目一个题库的固定目录，比较整理前后同一次 `buildViewData`：

| 科目数 | 整理前详情读取 | 当前详情读取 | 整理前耗时 | 当前耗时 |
| --- | ---: | ---: | ---: | ---: |
| 20 | 21 | 1 | 0.0092 ms | 0.0032 ms |
| 100 | 101 | 1 | 0.0273 ms | 0.0039 ms |
| 1000 | 1001 | 1 | 1.9192 ms | 0.0165 ms |

每组先预热 50 次，再运行 9 批、每批 100 次；耗时取各批平均值的中位数。两份完整展示数据逐项相等。详情读取为内存 Repository 调用次数，HTTP 请求数为零；这些数据衡量本机 Node 计算，不代表微信设备帧率。`bank-chapters.check.js` 回归检查当前投影的读取次数、科目状态和章节分组。

## 后端及运行时

题目修订、选项、附件和阅读材料采用批量读取；跨设备接力的周期请求已退出运行路径。异步同步、幂等、重试、死信恢复和监控继续提供可靠性保障。

隔离 PostgreSQL 中，用相同的 1000 道单选题比较同一题目读取器的逐题调用与批量调用。两种方式返回的题目、选项和答案逐项相等：

| 题量 | 逐题调用 SQL 次数 | 批量调用 SQL 次数 |
| --- | ---: | ---: |
| 20 | 80 | 4 |
| 100 | 400 | 4 |
| 1000 | 4000 | 4 |

检查入口为 `QuestionBatchPostgresTest`，日志中的 `QUESTION_BATCH_EVIDENCE` 同时记录耗时。这组数据衡量题目读取，不包含整次练习创建的写入、锁和权限检查。创建练习的指定题目范围校验及阅读材料修订也采用批量查询。

同一隔离 PostgreSQL 环境构造相同结构的单选题，先进行一次范围预览，再创建练习并读取固定设备快照：

该次测量包含练习创建写入与快照读取，使用相同设备凭据；登录、基础目录和范围预览的 SQL 及耗时不计入后两列。SQL 计数来自 MyBatis 拦截器，包含逐练习题目写入，不覆盖 JdbcTemplate。耗时为单次本地观察，不能据此推导稳定延迟或容量。日志标记为 `PRACTICE_PAYLOAD_EVIDENCE`。

小程序请求调度仍保留前台最多四并发、后台草稿最多一个槽位。微信实际上传包体、真机交互和并发容量需在对应环境记录；本次没有执行代码上传。源文件大小不能代替微信实际包体。

## 优化边界

当前整理减少目录无效计算和答题卡重复投影。SSE 使用原有长连接、五秒快照推送、认证检查和退避重连；队列确认、重试、死信与交卷屏障沿用现有实现。数据库结构、事务、缓存有效期和请求并发与基线一致。跨请求缓存、并发模型和数据库写入策略的调整需要独立的失效、恢复及容量证据。
