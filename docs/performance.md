## 后端及运行时

题目修订、选项、附件和阅读材料采用批量读取；跨设备接力的周期请求已退出运行路径。异步同步、幂等、重试、死信恢复和监控继续提供可靠性保障。

隔离 PostgreSQL 中，用相同的 1000 道单选题比较同一题目读取器的逐题调用与批量调用。两种方式返回的题目、选项和答案逐项相等：

| 题量 | 逐题调用 SQL 次数 | 批量调用 SQL 次数 |
| --- | ---: | ---: |
| 20 | 80 | 4 |
| 100 | 400 | 4 |
| 1000 | 4000 | 4 |

检查入口为 `QuestionBatchPostgresTest`，日志中的 `QUESTION_BATCH_EVIDENCE` 同时记录耗时。这组数据衡量题目读取，不包含整次练习创建的写入、锁和权限检查。创建练习的指定题目范围校验及阅读材料修订也采用批量查询。

后端版本 `690d1b38` 将练习条目创建、选项读取和判题更新批量化，认证合并为一次关联读取，交卷复用已经校验的题目与修订数据。CI 的相同题量用例记录如下：

| 题量 | 创建＋快照 MyBatis SQL | 已保存答案交卷 MyBatis SQL |
| --- | ---: | ---: |
| 20 | 31 | 19 |
| 100 | 31 | 19 |
| 1000 | 31 | 19 |

创建与快照计数覆盖两次 HTTP 请求；范围预览先完成。交卷计数覆盖一次 HTTP 请求，答案事先保存，随后完整提交答案并核对交卷响应与结果查询逐项相等。这些计数验证数据库往返随题量保持固定；新答案逐项保存、传输数据量和实际 CPU 成本仍随业务内容变化。CI 记录为 `PRACTICE_PAYLOAD_EVIDENCE` 和 `PRACTICE_FINISH_EVIDENCE`，容量以持续压测记录为准。

题库可用题目采用集合查询，练习读取使用共享锁，内容写入维持排他锁。HTTP 按客户端协商启用 gzip。认证每次请求读取当前账号与会话状态，沿用三十秒活跃时间更新间隔，撤销或凭据版本变化立即生效。普通账号读写不设固定配额；来源 IP 默认保留每六十秒六万次的固定窗口保护。

版本 `823a21ae` 使用实时可见题库视图，并在题库列表关联前分别汇总题量、可用题量和当前用户进度，减少重复扫描。节点默认最多同时处理 32 个普通业务请求，拥挤时返回 503 和 `Retry-After: 1`；这是在途请求保护，容量按实际活跃人数和完成吞吐衡量。入口拒绝计入监控，业务与身份审计继续保留。

内容缓存版本复用相同题目读取器：四种题型的真实 Redis／PostgreSQL 联测中，缓存命中后 MyBatis 查询从冷读的 4 次降为 1 次，返回内容相等；权限和当前题目状态仍实时读取。题库题量使用内容版本键，个人进度独立查询。该结果只衡量内容读取往返，整次练习仍包含认证、选题、写入和事务成本，承载收益以同档持续负载比较为准。入口增加有界短等待，默认等待容量 64、时限 100 毫秒；实际配置随各轮报告记录。

小程序请求调度仍保留前台最多四并发、后台草稿最多一个槽位。微信实际上传包体、真机交互和并发容量需在对应环境记录；本次没有执行代码上传。源文件大小不能代替微信实际包体。

## 验证范围

前端检查覆盖目录计算、答题卡投影及字段补丁。SSE 保留长连接、五秒快照推送、认证检查和退避重连。

后端保存继续使用幂等命令、持久化回执、重试、死信和交卷屏障。容量核对同时检查服务器已登记命令、最终 COMMITTED 状态、实际答案及成绩；HTTP 202 记录受理，不计为最终保存。版本、资源限制、负载与测试链路共同决定容量结论。
